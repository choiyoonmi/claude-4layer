# 클로드 4층 구조 — 무엇을 어디에 두는가

넷 다 "클로드에게 맥락을 주는 것"이다. 다른 건 **언제 읽히는가** 하나뿐이고, 설치 위치와 적용 범위가 거기서 갈린다.

| 층 | 언제 읽히나 | 비유 |
|---|---|---|
| **md** | 그 폴더에서 일하는 한 **매번 통째로** | 사규 — 출근하면 무조건 읽는 것 |
| **스킬** | 요청이 `description`과 맞을 **때만** | 업무 매뉴얼철 — 그 일 할 때만 꺼내는 것 |
| **플러그인** | 안에 든 스킬 기준 (자체는 포장) | 온보딩 패키지 — 매뉴얼+열쇠+계정 한 번에 |
| **메모리** | 관련될 때, 내가 안 적어도 | 인수인계 노트 — 같이 일하며 쌓인 것 |

## 답하는 순서

사용자 질문을 아래 순서로 통과시킨다. **처음 "예"가 나오는 곳이 답**이다.

1. 매번 무조건 지켜져야 하는가? (파일명 규칙·발송 금지·톤) → **md**
2. 특정 작업을 할 때**만** 필요한 긴 절차인가? (분석지 조판 규격) → **스킬**
3. 스킬 여러 개 + 커넥터를 남에게 통째로 넘겨야 하는가? → **플러그인**
4. 굳이 안 적어도 되는 취향·맥락인가? → **메모리에 맡긴다**
5. 개인정보가 대화에 들어가는가? → **시크릿 챗**(새 대화 오른쪽 위 유령 아이콘)

도입 순서는 **md → 스킬 → 플러그인**. 처음부터 플러그인을 권하지 말 것. 대부분은 md와 스킬 두 층에서 끝난다.

## 설치 위치 (CLI / 클로드 코드)

경로를 알려줄 때는 사용자 계정명을 실제 값으로 바꿔서 보여준다. Windows 기준:

```
개인 md      C:\Users\<계정>\.claude\CLAUDE.md
프로젝트 md   <작업폴더>\CLAUDE.md                     ← 상위와 겹쳐서 함께 읽힘
개인 스킬     C:\Users\<계정>\.claude\skills\<이름>\SKILL.md
프로젝트 스킬  <작업폴더>\.claude\skills\<이름>\SKILL.md
플러그인      C:\Users\<계정>\.claude\plugins\cache\<마켓>\<플러그인>\<버전>\
```

macOS/Linux는 `~/.claude/` 로 동일한 구조.

- 스킬 **폴더 이름이 곧 명령어 이름**이다. `skills\my-review\` → `/my-review`
- 파일 이름은 반드시 대문자 `SKILL.md`
- 플러그인 안의 스킬은 `플러그인이름:스킬이름`으로 불린다. 예) `/claude-4layer:layer-map`
- 플러그인 캐시는 `/plugin install`이 자동으로 채운다. 손으로 만지지 않는다.

## 환경별 차이 — 여기서 대부분 헷갈린다

| 항목 | 웹 | 데스크톱 앱 | 코워크 | CLI |
|---|---|---|---|---|
| md 두는 곳 | 프로젝트 지침 + 지식 업로드 | 앱엔 칸 없음(통로 역할) | 전역·폴더 지침, 폴더 안 CLAUDE.md | `~/.claude/` + `./` 계층 |
| 스킬 설치 | ZIP 업로드 | ZIP 업로드 | ZIP 업로드 | 폴더째 복사 |
| 플러그인 | 스킬만 동작 | 스킬만 동작 | 전부 동작 | 전부 동작 |
| 훅·서브에이전트 | ✕ | ✕ | ○ | ○ |
| 챗 메모리 | ○ | ○ | ✕ (프로젝트 메모리만) | 자동 메모리 별도 |

웹·코워크는 폴더가 아니라 **Customize → Skills**에서 스킬 폴더를 ZIP으로 압축해 올린다. 업로드한 스킬은 계정에 붙어 웹·데스크톱·코워크에 모두 뜬다. 단 코드 실행 기능이 켜져 있어야 항목이 보인다.

## 자주 나오는 증상 → 원인

- **"스킬 설치했는데 `/이름`이 안 떠"** → 폴더가 `.claude\skills` **바깥**에 있다. 가장 흔한 원인. `skill-path` 스킬로 진단·이동한다.
- **"스킬이 있는데 안 불려와"** → `description`이 "언제 쓰는지"를 안 말하고 있다. 기능 설명이 아니라 **발동 조건**을 쓴다.
- **"웹에서 다 설명했는데 코워크가 모른다"** → 챗 메모리는 코워크에서 지원되지 않는다. 코워크에서는 프로젝트로 묶었을 때만 기억이 이어진다.
- **"웹 프로젝트 지침이 CLI에 안 따라온다"** → 세 곳은 각각 별개 자리다. 복붙하지 말고 **웹엔 요약본, 코워크·CLI엔 원본**으로 나눈다.
- **"사무실에서 깐 플러그인이 집 노트북에 없다"** → 로컬 추가 플러그인은 계정이 아니라 **기기**에 붙는다. 깃허브 마켓플레이스로 올리면 웹·코워크·CLI가 같은 것을 본다.
- **"플러그인에 CLAUDE.md 넣었는데 규칙이 안 먹는다"** → 플러그인 루트의 CLAUDE.md는 프로젝트 컨텍스트로 로드되지 않는다. 지시문은 **스킬 안에** 넣어야 한다.

## md를 쓸 때 지킬 것

- **150~200줄이 실질 한계선.** 매번 통째로 들어가므로 길면 뒤쪽부터 무시된다.
- 사고로 이어지는 **금지 규칙은 맨 앞**에. (발송 금지, 개인정보 반출 금지, 정답 노출 금지)
- 20줄 넘는 규칙은 하위 파일로 빼고 본체엔 한 줄 참조만 남긴다.
- **상상해서 채우지 않는다.** 2주 써 보고 "또 설명하게 되네" 싶은 것만 추가한다.

## 보안 한 줄

플러그인에는 내 컴퓨터에서 다른 프로그램과 같은 권한으로 도는 **로컬 MCP 서버**가 포함될 수 있다. 설치 전에 내용을 열어 보게 하고, 학생 개인정보가 있는 환경이라면 신뢰할 수 있는 출처만 설치하도록 안내한다.
