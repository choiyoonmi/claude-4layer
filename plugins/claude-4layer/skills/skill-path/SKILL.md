# 스킬이 안 먹힐 때 — 진단과 복구

증상은 거의 항상 셋 중 하나다. **위에서부터** 확인한다. 추측하지 말고 점검 스크립트를 먼저 돌린다.

1. 스킬 폴더가 `.claude/skills` **밖**에 있다 ← 1순위
2. `SKILL.md`가 없거나 파일명이 틀렸다 (반드시 대문자 `SKILL.md`)
3. 프론트매터의 `description`이 "언제 쓰는지"를 말하지 않는다

## 1단계 — 점검 스크립트를 돌린다

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File "${CLAUDE_PLUGIN_ROOT}/skills/skill-path/scripts/check-skills.ps1"
```

한 번에 다섯 가지를 보여준다. 지금 읽히는 CLAUDE.md, 개인 스킬, 프로젝트 스킬, 설치된 플러그인, 그리고 **제자리 밖에 방치된 스킬**.

기본은 보기만 한다. 아무것도 옮기지 않는다.

옵션:

- `-Roots '<폴더>'` — 찾을 범위를 좁힌다. 홈 전체가 느리면 이걸 쓴다.
- `-Depth <n>` — 내려갈 단계. 기본 4.
- `-Fix` — 제자리 밖 스킬을 실제로 이동한다. **아래 2단계를 먼저 거친다.**

macOS/Linux거나 스크립트를 못 돌리는 상황이면 직접 확인한다.

```bash
ls ~/.claude/skills/            # 개인 스킬
ls ./.claude/skills/            # 프로젝트 스킬
find ~ -name SKILL.md -not -path '*/.claude/skills/*' -not -path '*/.claude/plugins/*' 2>/dev/null
```

## 2단계 — 옮기기 전에 반드시 확인받는다

`-Fix`는 파일을 실제로 이동한다. 바로 실행하지 말고 이렇게 한다.

1. 스크립트가 찾은 목록을 **사용자에게 그대로 보여준다** (경로와 옮겨질 명령어 이름)
2. 그중 **진짜 스킬이 아닌 것이 섞였는지** 같이 확인한다. 남의 저장소를 clone 해 둔 것, 참고용으로 받아 둔 예제, 작업 중인 초안일 수 있다
3. "이 중에 옮길 것을 골라 주세요"라고 묻는다
4. 답을 들은 뒤에 이동한다

전부 옮겨도 된다고 하면 `-Fix`를 쓰고, 일부만이면 해당 폴더만 직접 옮긴다.

```powershell
Move-Item "<원래 경로>" "$HOME\.claude\skills\<스킬이름>"
```

**이동 후에는 새 세션을 열어야 반영된다.** 이 점을 반드시 알려 준다.

## 3단계 — 옮겼는데도 안 뜨면

이 순서로 본다.

- **파일명** — `Skill.md`, `skill.md`, `SKILL.MD` 전부 안 된다. 대문자 `SKILL.md`.
- **구조** — `skills\<이름>\SKILL.md` 여야 한다. `skills\SKILL.md`처럼 폴더 없이 두면 안 된다.
- **프론트매터** — 파일 **첫 줄**이 `---` 여야 한다. 앞에 빈 줄이나 설명이 있으면 인식되지 않는다.
- **이름 충돌** — 같은 이름의 스킬이 개인·프로젝트·플러그인에 겹쳐 있으면 하나만 뜬다. 스크립트 2·3·4절 목록을 대조한다.
- **명령어 이름** — 슬래시 명령은 **폴더명** 기준이다. 프론트매터의 `name`과 폴더명이 다르면 폴더명이 이긴다. 스크립트가 이 불일치를 `[!]`로 표시한다.
- **플러그인 스킬** — `/이름`이 아니라 `/플러그인이름:스킬이름`으로 부른다.

## 4단계 — 있는데 "안 불려온다"면 description 문제다

폴더도 맞고 파일도 맞는데 클로드가 안 쓴다면, 원인은 거의 `description`이다. 스킬은 요청이 description과 맞을 때만 로드된다.

`description`은 **기능 설명이 아니라 발동 조건**이어야 한다.

- 나쁨 — `시험지를 만드는 스킬`
- 좋음 — `영어 시험지를 만들 때 사용. "시험지 뽑아줘", "단원평가 만들어줘", 특정 단원·범위를 말하며 문항을 요청할 때 작동.`

고칠 때는 사용자가 **실제로 칠 법한 말**을 서너 개 넣는다. 사용자에게 "이 스킬을 쓸 때 보통 뭐라고 입력하세요?"라고 물어보고 그 표현을 그대로 넣는 것이 가장 확실하다.

## 하지 말 것

- 확인 없이 `-Fix`를 실행하지 않는다.
- 사용자의 스킬 파일 내용을 마음대로 고쳐 쓰지 않는다. `description`을 고칠 때도 바뀐 부분을 보여주고 동의를 받는다.
- 원인을 찾기 전에 "다시 설치해 보세요"라고 하지 않는다. 위 순서로 짚으면 대부분 1단계에서 끝난다.
