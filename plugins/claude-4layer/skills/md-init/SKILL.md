# CLAUDE.md 초안 만들기

md는 **매번 통째로 읽히는 층**이다. 그래서 이 스킬의 목표는 "많이 쓰기"가 아니라 **꼭 필요한 것만 짧게 쓰기**다.

## 절대 지킬 것

1. **완성본은 150줄을 넘기지 않는다.** 넘으면 뒤쪽부터 무시된다. 넘칠 것 같으면 상세를 `rules/` 하위 파일로 빼고 본체엔 한 줄 참조만 남긴다.
2. **사고로 이어지는 금지 규칙을 맨 앞에 둔다.** 발송 금지, 개인정보 반출 금지, 배포 전 확인, 정답 노출 금지 같은 것.
3. **추측으로 채우지 않는다.** 폴더에서 실제로 확인한 것과 사용자가 직접 말한 것만 쓴다. "아마 이런 규칙이 있겠지"로 줄을 늘리지 않는다.
4. 기존 `CLAUDE.md`가 있으면 **덮어쓰기 전에 읽고 보여준다.** 무엇을 남기고 무엇을 지울지 사용자가 정하게 한다.

## 순서

### 1단계 — 폴더를 먼저 본다 (질문보다 먼저)

사용자에게 묻기 전에 스스로 확인한다.

- 파일 목록과 확장자 분포 (`.html` 뭉치인가, `.py` 빌더인가, 문서·PDF뿐인가)
- `package.json`·`wrangler.jsonc`·`requirements.txt` 등 빌드·배포 설정
- `.git` 유무와 리모트 주소
- 기존 `CLAUDE.md`, `.claude/` 폴더
- README나 눈에 띄는 진입 파일

여기서 알아낼 수 있는 것은 **묻지 않는다.** 언어·프레임워크·배포처는 대개 파일이 말해 준다.

### 2단계 — 모자란 것만 묻는다 (최대 3개)

파일로 알 수 없는 것만 고른다. 좋은 질문은 이런 것들이다.

- 이 폴더에서 **매번 반복 설명하게 되는 것**이 뭔가?
- 절대 하면 안 되는 일이 있나? (자동 배포, 메일 발송, 학생 이름 외부 전송)
- 결과물을 받는 사람이 누구인가? (학부모 / 학생 / 나만)

한 번에 다 묻지 말고, 답을 듣고 필요하면 하나 더 묻는다.

### 3단계 — 템플릿을 고른다

`templates/` 안에서 폴더 성격에 맞는 것을 **출발점으로만** 쓴다. 그대로 복사하지 말고 1·2단계에서 확인한 사실로 채워 넣고, 해당 없는 절은 지운다.

| 폴더 성격 | 템플릿 |
|---|---|
| 안내문·리포트·상담자료 등 행정 문서 작업 | `templates/hagwon-admin.md` |
| 교재·학습지·문제 제작 (빌더 스크립트, PDF/HTML 산출) | `templates/content-build.md` |
| 웹앱·서버 저장소 (배포가 걸려 있음) | `templates/app-dev.md` |

세 개 중 어디에도 안 맞으면 템플릿 없이 아래 뼈대로 짧게 쓴다.

```markdown
# <폴더 한 줄 설명>

## 하지 말 것
- (금지 규칙 1~3개)

## 이 폴더의 사실
- (구조·진입점·배포처 등 확인된 것)

## 작업 방식
- (반복 설명을 없애는 규칙 3~6개)
```

### 4단계 — 쓰고, 근거를 보여준다

`CLAUDE.md`를 쓴 뒤 **한 줄짜리 요약**으로 무엇을 넣었는지 말하고, 특히 이렇게 알린다.

- 사용자가 직접 말한 규칙과, 내가 폴더를 보고 추론한 규칙을 **구분해서** 알려 준다
- 추론한 것은 "이거 맞나요?" 한 번 확인받는다
- 완성본 줄 수를 알려 준다 (150줄 한계선 대비)

### 5단계 — 다음에 뭘 추가할지 알려 준다

마지막에 반드시 이 안내를 붙인다.

> 앞으로 작업하다가 **"아, 이것도 또 설명하게 되네"** 싶은 순간이 옵니다. 그 한 줄이 여기 추가할 내용입니다. 미리 상상해서 채우지 마세요.

## 넣지 말 것

- 클로드가 이미 잘 하는 일반론 ("깔끔한 코드를 작성한다", "주석을 잘 단다")
- 파일을 열어 보면 아는 사실을 길게 옮겨 적은 것 (폴더 구조 전체 나열)
- 한 번 쓰고 말 일회성 작업 지시 — 그건 그냥 대화에서 시킨다
- 긴 절차 (20줄 넘는 조판 규격, 채점 규칙) — 그건 **md가 아니라 스킬**로 만든다. 그렇게 안내한다.
- 개인정보 자체 (학생 실명 명단, 연락처). 규칙은 쓰되 데이터는 쓰지 않는다.
